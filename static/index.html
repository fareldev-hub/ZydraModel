Kelola API keys

Masuk dengan AUTH master untuk mengelola key. Nilai key ditampilkan sekali; database hanya menyimpan hash.

    1. Chat teks

    Body utama memakai model dan array messages. Respons teks ada di choices[0].message.content.

    BASE_URL="http://localhost:8000"
API_KEY="ganti-dengan-password-AUTH"

curl "$BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"zydra","messages":[{"role":"user","content":"Jelaskan fotosintesis secara singkat."}]}'

    2. JavaScript fetch

    const BASE_URL = "http://localhost:8000";
    const API_KEY = "ganti-dengan-password-AUTH";

    const response = await fetch(`${BASE_URL}/v1/chat/completions`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    model: "zydra",
    messages: [{ role: "user", content: "Halo, Zydra!" }]
  })
});

const data = await response.json();
console.log(data.choices[0].message.content);

    3. Model, instruksi, dan status

    Contoh berikut memakai cURL. Route status dapat dipanggil tanpa API key.

    # Daftar model (perlu API key)
curl "$BASE_URL/v1/models" -H "Authorization: Bearer $API_KEY"

# Baca instruksi (perlu API key)
curl "$BASE_URL/v1/instructions" -H "Authorization: Bearer $API_KEY"

# Ubah instruksi (perlu API key)
curl "$BASE_URL/v1/instructions" \
  -X PUT \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"instructions":"Jawab ringkas dan gunakan Bahasa Indonesia."}'

# Cek health, tahap setup, dan readiness (tanpa API key)
curl "$BASE_URL/health"
curl "$BASE_URL/status"
curl -i "$BASE_URL/ready"
